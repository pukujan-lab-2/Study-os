# Issue #76: [P4] First-class auxiliary study artifacts with durable state

- State: open
- Opened by Pukujan on 2026-09-08
- Original: https://github.com/Pukujan-lab/Study-os/issues/76

## Purpose

Track a live PAM-C product gap surfaced while using the real Study OS GPT: the learner-facing GPT can propose useful auxiliary artifacts such as a compact DSA interview/cram manual, but Study OS currently has no explicit durable/versioned object governing that promise across sessions.

Parent architecture: #63
Live integration context: #66

## Observed failure shape

```text
learner requests/accepts useful reference artifact
→ GPT conversationally promises "we'll build this alongside"
→ no canonical artifact id/version/coverage/provenance
→ no deterministic persistence/resume contract
→ future chats may forget, duplicate, drift, or implicitly fork curriculum
```

The proposed content itself is not the defect. The defect is lack of first-class Study OS state for an accepted learner-facing artifact.

## Authority boundary

Canonical course/progression remains owned by the deterministic controller.

Auxiliary study artifacts may summarize, reactivate, organize, or review learned material, but they must not silently become a second curriculum/progression graph or create mastery/prerequisite claims.

## Candidate contract

```yaml
StudyArtifact:
  artifact_id: string
  artifact_version: string
  artifact_type: cram_manual | cheat_sheet | review_notes | worked_examples | other
  title: string
  purpose: string
  status: proposed | active | complete | archived
  source_concept_refs: [string]
  coverage:
    concept_ref: not_started | in_progress | complete
  content_ref: string | null
  representation_refs: [string]
  learner_request_evidence_refs: [string]
  canonical_progression_authority: false
  created_at: timestamp
  updated_at: timestamp
```

Possible operation family:
- `propose_auxiliary_artifact`
- `accept_auxiliary_artifact`
- `update_auxiliary_artifact`
- `review_auxiliary_artifact`
- `archive_auxiliary_artifact`

Exact schema/storage is design work; reuse existing durable evidence/artifact substrates where semantics fit.

## Required invariants

1. Artifact creation/update is explicit and persisted.
2. Same artifact resumes across chats by stable identity/version.
3. Artifact cannot silently satisfy prerequisites/mastery or advance canonical course state.
4. Artifact content is traceable to canonical concepts/source material where applicable.
5. Coverage state belongs to the artifact and is distinct from learner mastery.
6. GPT may propose/realize content but may not silently fork/replace the canonical curriculum.
7. Updates preserve provenance and do not rewrite historical learner evidence.
8. Learner can intentionally archive/replace an artifact without losing historical lineage.

## Initial acceptance cases

### ART-001 — create accepted cram manual
Learner requests a compact DSA interview cram guide. Study OS creates one durable artifact with stable ID/version and explicit non-progression authority.

### ART-002 — cross-chat resume
A later chat resumes the same artifact, its existing structure, and coverage state rather than inventing a new manual.

### ART-003 — update from learning trajectory
A reviewed topic can update the artifact page/coverage without automatically changing canonical mastery/progression.

### ART-004 — no hidden curriculum fork
GPT cannot add a new progression path merely because the artifact contains additional topics.

### ART-005 — provenance
Artifact updates remain attributable to source concepts/evidence and module/prompt/version context where relevant.
