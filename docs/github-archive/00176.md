## What

Rewires the Big O teach / explain-again / worked-example frames to the simple **4-class `growth_curve` + `series_multi`** visual (O(1), O(log n), O(n), O(n²)), with per-step `highlight_label` naming the class being taught. Vector-only, code-native; no new assets, no new visual component.

- Every Big O step now defaults to one `growth_curve` frame with a 4-class `series_multi` plot; `highlight_label` points at the class the step teaches.
- Explain-again and the worked example rotate to a second card (same four curves, single-class or different highlight).
- `growth_workers` (invent-first stick-figure metaphor Alex rejected) is **removed from the default teach path**.
- The per-class `growth_table` frames that rendered as the unreadable flat flex row are replaced on the default path.
- `presentation_raw` (the `growth_table` rollback used by `STUDY_OS_TEACH_VISUAL_V1=0`) is untouched, so the legacy path still works unchanged.

## One renderer gap found and closed

The brief assumed `GrowthCurve.tsx` already supported the highlight prop. It did not: `series_multi` was supported, but `highlight_label` was a dead key that the component ignored, so the per-step highlight would have been inert and every step would have shown four identical curves. Minimal change to the existing component (no new component, no refactor): the taught series keeps full opacity and a thicker stroke, the others dim, and the highlight is named in the accessible label. `highlight_label` added to the `GrowthCurveFrame` type.
