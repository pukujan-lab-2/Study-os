## Research/product question
Can the player survive a worked-example card and a back/Resume cycle without ever
rendering a blank screen?

## Root cause
`engine.adapt(..., "example")` stored `worked_example = {solution_md, frames}` and
`engine.view` passed it through `_strip_server_only`, which deletes `solution_md`.
The client therefore received `{frames: []}` with no `md`/`steps_md`; `Player.tsx`
took the `steps_md.map` branch and threw during render. With no error boundary the
whole React root unmounted, leaving the empty lavender shell. Browser back kept the
dead root, and Resume remounted the same session still in `card_mode=worked_example`
with the stripped payload, so it blanked again.

## Changes
- `engine.view` maps the stored `solution_md` onto the public `md` field and keeps
  frames renderable; `solution_md` still never appears in a view. A card with no
  solution text returns a shaped object instead of a stripped payload.
- `web/src/player/workedExample.ts` + `WorkedExampleCard.tsx` normalise
  `md`/`steps_md`/`frames` and render an empty state rather than throwing.
- `web/src/ErrorBoundary.tsx` wraps `main`/`App`/`Player` with a recoverable
  Retry / Go home card.
- `Player.tsx` clears stale view/error on session change, clears sticky load errors
  on success, and shows a bounded load-error UI instead of a bare paragraph.
- `CompanionPanel` adapt/back failures keep the prior card and post a system line.
