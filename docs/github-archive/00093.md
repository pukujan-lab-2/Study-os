# Issue #93: [WebApp] Analytics: first-party event tracker into Postgres plus Metabase-ready SQL views (no PostHog)

- State: open
- Opened by Pukujan on 2026-09-24
- Original: https://github.com/Pukujan-lab/Study-os/issues/93
- Labels: enhancement

## Why this matters
Alex wants to see what works: learning progress, frustration, which operations and representations help, and tutor cost and quality.

## Outcome
`analytics.*` SQL views (the metric layer) and Metabase OSS on gravebuster, reachable on the tailnet only. Starter dashboards: learner progress, UX friction, tutor quality/cost, and retention. DuckDB exports for ad-hoc work. Power BI stays optional: Desktop can read the same views over Tailscale, but it is not on the critical path (Windows-only gateway, Pro license needed for sharing and refresh).

## Acceptance criteria
- [ ] Metrics are defined in SQL views with tests on fixture data.
- [ ] Metabase connects with the read-only analytics role and is not publicly exposed.

Scope update from the deep-research report (docs/webapp/DEEP_RESEARCH.md §1.4, §7.3; adopted in docs/webapp/RESEARCH.md §0/§5):
- The Postgres append-only log with **xAPI-shaped events** is the source of truth.
- **Metabase** on Postgres handles learning metrics.
- **PostHog Cloud** receives a server-side mirror of allowlisted non-PII UX events (funnels, retention, flags, experiments), with IP capture off and no autocapture or replay.
- **Power BI is for aggregates only.**
- Experiment arm and propensity are logged from day one.

**Pukujan commented, 2026-09-24**

**D018 (owner amendment to D017, 2026-09-24):** no PostHog. All UX and learning events go to Postgres only. Slice 1: a small first-party frontend tracker (page views, clicks on key controls, step shown/answered, hint requests, time on step, idle/tab-away, client errors) batches events to `POST /api/events` → `ux.event` (with session and subject ids, allowlisted enums/ids only, no free text). Metabase-ready SQL views: `analytics.v_daily_active_learners`, `v_step_funnel`, `v_drop_off`, `v_hint_rate`, `v_accuracy_by_concept`, `v_time_on_step`, plus the xAPI-shaped `v_learning_event` and `v_decision`. Session replay is tracked separately in #98 (rrweb). Implemented in SOS-0004 (#99).
