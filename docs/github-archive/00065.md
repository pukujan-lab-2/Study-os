# Issue #65: [P4/PIR] Lossless Pedagogical IR and byte-backed golden compilation

- State: open
- Opened by Pukujan on 2026-09-05
- Original: https://github.com/Pukujan-lab/Study-os/issues/65

## Purpose

Make the Pedagogical IR (PIR) the trustworthy semantic core of Study OS before expanding the deterministic tutor/controller.

The immediate failure motivating this work is concrete: the complete 2026-09-04 Sliding Window calibration transcript contained an explicit, learner-calibrated `enumerate(a)` teaching sequence, yet later reasoning over compressed summaries incorrectly treated `enumerate` as potentially missing. The raw transcript survived; the derived/retrieval representation lost important pedagogical state.

This issue defines the specification-first program for preventing that class of omission, semantic compression, invented bridge, representation drift, and false reconstruction.

Relationship to #63: #63 remains the P4 controller/product tracker. This issue is the blocking PIR/evidence-compilation subprogram that must establish a trustworthy executable trajectory before the runtime controller is allowed to treat a golden as authoritative.

## Core thesis

```text
RAW BYTES
   ↓
BYTE-ADDRESSED TURN/EVIDENCE IR
   ↓
EXACT CONTEXT FRAMES
   ↓
PEDAGOGICAL ANNOTATION IR
   ↓
STATE / REPRESENTATION TRANSITIONS
   ↓
REVIEWED GOLDEN TRAJECTORY
   ↓
DETERMINISTIC CONTROLLER
```

Every abstraction is lossy. Therefore every abstraction must retain a reversible, mechanically validated path to the exact evidence from which it was derived.

Semantic equivalence does not imply pedagogical equivalence. An evidenced intermediate bridge may not be removed merely because its endpoints are semantically equivalent.

## Repository/module boundary

Mirror the versioned-module discipline used by `project-assurance-modules` rather than burying everything in the Study OS runtime.

### `Pukujan/Study-os`

Adopter/runtime and canonical learner/course data owner.

- owns private/local raw learner evidence and session state;
- consumes a pinned PIR module revision;
- owns Study-OS-specific controller integration;
- does not copy hidden benchmark answers into runtime context;
- does not require FOSSIL for canonical operation.

### Proposed separate versioned PIR repository

Create a dedicated repository/package analogous to the PAM pattern, tentatively `study-os-pedagogy-ir`.

It should own only portable PIR contracts and deterministic tooling:

```text
schemas/
specs/
modules/
fixtures/        # public/synthetic/redacted only
src/
tests/
docs/
```

Pre-v1 adopters pin an exact Git revision; mutable branch names and the Python package version are not sufficient methodology/IR identity.

### `Pukujan/study-os-benchmarker`

Independent public benchmark/evaluation repository.

- common adapter contract for baseline/donor architectures;
- historical public/redacted regression fixtures;
- adversarial/mutation/metamorphic benchmark generators;
- repeated-run nondeterminism measurements;
- ablation harness;
- donor/reference adapters (free-form, CTAT-like, StratL-style, ScaffoldLM-style, MWPTutor-style as feasible);
- MUST NOT contain private raw transcripts or sealed holdout answers.

### Hidden holdouts

Do not create a new repository merely for symmetry. When the first genuinely sealed holdout exists, keep it in a private/local evaluation store inaccessible to runtime/development agents. Once exposed during debugging, retire it into the public regression suite and replace it.

### FOSSIL

FOSSIL remains generic evidence/provenance infrastructure, not the pedagogy controller.

Study OS/PIR owns pedagogical semantics. A FOSSIL adapter may export artifact/span/provenance/lineage records without making FOSSIL a runtime dependency or allowing derived claims to replace raw evidence.

## Runtime/tooling baseline

Prefer a small conservative Python stack:

- Python 3.12/3.13;
- raw `bytes` at L0;
- stdlib `hashlib.sha256`;
- stdlib `sqlite3` for local deterministic persistence where needed;
- frozen dataclasses for lowest-level byte/span objects where appropriate;
- Pydantic v2 strict/frozen/`extra=forbid` for typed boundaries;
- JSON Schema Draft 2020-12 via `jsonschema` as independent wire-contract validation;
- pytest;
- Hypothesis;
- branch coverage (`coverage.py` / `pytest-cov`);
- `mutmut` on the trust kernel;
- CrossHair selectively on small pure invariants;
- `mypy --strict`;
- Ruff;
- GitHub Actions/CI.

No ORM, vector DB, LangGraph, Redis/Kafka, generic agent framework or distributed infrastructure in v0.1 unless a demonstrated requirement forces reconsideration.

TLA+ is deferred until the deterministic controller/state machine has stable enough semantics to model. Lean 4 is explicitly not a v0.1 requirement.

## Non-negotiable invariants

1. Raw evidence is immutable and byte-addressable.
2. Hashes are computed over original bytes before normalization/decoding.
3. A verbatim turn/span must reconstruct exactly from its source bytes.
4. Repeated identical text is distinguished by artifact + byte location + identity, never text search alone.
5. Every source turn receives an explicit disposition; no silent omission is permitted.
6. `coverage == 100%` means only that every source turn was accounted for, not that the golden is complete.
7. Every derived annotation/node/edge requires resolvable source evidence or is explicitly marked unresolved/proposed.
8. Evidence, derived interpretation, reviewed golden and runtime state are separate layers.
9. Historical interpretation may be superseded; source evidence is never rewritten to fit a new model.
10. An evidenced pedagogical bridge cannot be removed solely because endpoints are semantically equivalent.
11. Runtime graph traversal must not replace explicit required pedagogical ordering.
12. Representation state and negative constraints are machine-readable, not prose-only hints.
13. Private raw transcripts and sealed holdout answers do not enter public repositories.
14. Model output never becomes canonical merely because another model agrees with it.
15. Compiler/version changes cannot silently rewrite historical golden identity.

## Validation pyramid

### V0 — static/schema

- Ruff;
- mypy strict;
- Pydantic strict validation;
- independent JSON Schema validation;
- Pydantic/JSON-Schema acceptance parity fixtures;
- SQLite FK/UNIQUE/CHECK constraints where persistence is used.

### V1 — byte/span integrity

- original bytes -> ingest -> reconstruction is byte-identical;
- SHA-256 round trip exact;
- valid span boundaries;
- no normalization before evidence hashing;
- CRLF/LF preserved;
- trailing whitespace preserved;
- Unicode/emoji/zero-width data preserved;
- malformed/EOF/truncation cases handled explicitly;
- delimiter-like text inside code blocks cannot create false turns.

### V2 — property/metamorphic

Use Hypothesis and explicit metamorphic relations.

Examples:

- arbitrary valid slice reconstructs exact bytes;
- partition/rejoin preserves artifact;
- serialize/deserialize is identity for valid IR;
- changing one source byte changes containing hashes but not unrelated earlier objects;
- adding a later unrelated turn does not change an earlier bounded context frame;
- annotation changes cannot change raw evidence hash;
- ordering changes must change trajectory/context identity;
- equivalent serialization order cannot change canonical semantic identity where canonicalization says it should not.

### V3 — historical fixture tests

Use public synthetic/redacted fixtures plus the complete private September-4 transcript locally.

September-4 gate must prove without relying on summaries/golden files that the source contains and contextualizes calibrated sequences including, at minimum, the known `enumerate(a)` explanation/exercise/validation sequence.

Historical fixture changes require explicit evidence review; do not blindly update snapshots.

### V4 — implementation mutation testing

Run `mutmut` against the trust kernel:

- span math;
- hash checks;
- evidence resolution;
- coverage accounting;
- compiler ordering;
- transition authorization;
- answer-reveal/forbidden-state validation.

Critical surviving non-equivalent mutants should be zero before v0.1 is frozen.

### V5 — data/specification mutation tests

Mutate valid trajectories themselves, not only Python code:

- remove each required node one at a time;
- remove/alter evidence refs;
- reorder turns;
- combine two pedagogical steps;
- skip an evidenced bridge;
- replace same-chart validation with detached text;
- reveal an exercise answer;
- introduce a future concept early;
- change an immutable symbol/term;
- mutate representation family;
- fabricate a learner outcome;
- convert unresolved evidence into asserted golden state.

Required mutations must be rejected or surfaced as a specific unresolved/discontinuity error.

### V6 — semantic-compression adversarial suite

Encode the actual dangerous "reasonable improvements":

- `S[0] -> S[i]` skipped;
- explicit `S[2] -> S[i]` generalized prematurely;
- `if i != 0 -> else` bridge removed;
- validation drops array/index/box;
- `S[i]` renamed to `window_sum` without authorization;
- comparison introduced before learner writes `S[i]`;
- `range(k)` introduced before the fixed-window scalability bridge;
- explanation + probe collapsed when the golden requires two states.

Endpoint semantic correctness must not excuse an illegal path mutation.

### V7 — full historical replay

Replay the complete September-4 learner responses through the compiled trajectory.

Required:

- same control-state/node sequence;
- same accepted/rejected branch decisions;
- same required question/template IDs where frozen/parameterized;
- no invented learner outcome;
- every runtime transition maps back to evidence-backed golden state.

Do not infer mastery from completion of the historical transcript.

### V8 — independent benchmark repository

`study-os-benchmarker` compares:

- free-form LLM baseline;
- current prompt/controller baseline;
- CTAT-like behavior graph baseline;
- StratL-style transition control;
- ScaffoldLM-style plan + assessment;
- MWPTutor-style FST where reproducible;
- Study OS PIR.

Use a normalized candidate interface and the same machine-scored contracts.

Run nondeterministic candidates repeatedly over frozen states and report rates rather than cherry-picked examples:

- legal-next-transition rate;
- bridge-preservation rate;
- representation-preservation rate;
- answer-leakage rate;
- future-information leakage;
- question-contract compliance;
- invented-outcome rate;
- provenance resolution rate;
- variance across repeated runs.

### V9 — ablations

Remove one PIR feature at a time and measure degradation:

- representation state;
- forbidden future information;
- fixed/parameterized question contract;
- correction trajectory;
- mutation contract;
- learner-outcome gate;
- provenance-backed prerequisite/path constraints.

A feature that adds complexity without measurable or invariant-level value should not be retained merely because it sounds useful.

### V10 — sealed hidden holdouts

Only after public/historical fidelity is stable.

Hidden cases test whether the system can detect missing prerequisites/bridges not explicitly encoded in the visible golden.

- runtime/development agent must not read expected answers;
- exposed holdout becomes a normal regression fixture and is retired as a holdout;
- benchmark report distinguishes historical fidelity from prospective discovery/generalization.

### Later — formal controller verification

Once controller semantics stabilize, evaluate TLA+ for safety/liveness properties such as:

- no unauthorized advancement;
- no concurrent active trajectory states where forbidden;
- no loss of historical evidence;
- correction/retry/verify cannot bypass required gate;
- state-machine implementation traces refine the formal model.

Do not treat a formal model as assurance unless refinement tests connect it to implementation behavior.

## External donor/research strategy

Do not integrate all donor systems into production at once.

Benchmark separately first, then adopt only components that improve the common evaluation.

- CTAT: ontology/design precedent for explicit behavior graphs, correct/incorrect/alternative paths and hints; do not assume license permits production reuse.
- StratL: candidate OSS donor for transition/intention graph concepts/implementation where license and reproducibility permit.
- ScaffoldLM: donor/reference for stable plan + progress + assessment loop and ablation methodology.
- MWPTutor: finite-state-pedagogy + bounded-LLM reference/baseline; do not make it a dependency unless reproducible packaging is demonstrated.

Study OS novelty should remain narrow: lossless transcript -> evidence-backed pedagogical microstate compilation -> constrained executable trajectory.

## v0.1 completion criterion

PIR v0.1 is not complete because schemas exist or tests are green in isolation.

It is complete when a fresh agent/process can take the complete September-4 private transcript and, without relying on existing summaries/goldens:

1. preserve the source byte-for-byte;
2. enumerate and account for every turn;
3. resolve exact contextual evidence;
4. reconstruct the reviewed pedagogical states and failure/repair paths;
5. compile the complete golden trajectory without invented edges or omitted evidenced bridges;
6. reject the known semantic-shortcut/adversarial mutations;
7. replay the historical learner interaction through the same control-state sequence;
8. produce an auditable report tying every derived golden node/edge back to exact source evidence.

Only then should #63 treat PIR-backed golden execution as a trusted controller input.
