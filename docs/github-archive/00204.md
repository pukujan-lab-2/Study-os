# Study OS v2 — end-to-end learner experience and teaching-core reset

**Owner feedback, 2026-10-08:** The problem is not only the Big O game. Login/guest entry, onboarding, navigation, problem showcase, pedagogical decomposition, explanations, AI usage, linguistic control, and term/ontology grounding fail as one user journey. The interactive sticks-and-boxes Big O reference is a useful exemplar; the surrounding learning experience is not acceptable.

**Status:** Architecture/design proposal, NOT owner-approved implementation and NOT authorization to delete the current application. Keep main/live stable.

## Evidence seen on main
- `web/src/App.tsx` routes both legacy `/lesson/:id` and new `/play/:id`; active landing `Try.tsx` hardcodes the primary CTA to first listed fractions lesson.
- `web/src/styles.css` limits the app shell to 720px; `TeachRenderBox.module.css` / `SticksBoxesComplexity.module.css` cap the interactive surface at about 28rem.
- `src/study_os/web/player/human_rewrite.py` is a style/length scrubber, not a concept-definition or semantic-integrity validator.
- `src/study_os/web/player/prompts/tutor.v3.md` asks for frame indices selecting/reordering existing frames; it does not guarantee semantic algebra/graph/interaction synthesis.
- `docs/research/pedagogical-decomposer.md` describes a research + static human-eval prototype, with no production pipeline; `#118` describes the unshipped rebuild. No first-class tracked ontology package was found in the inspected default-branch tree. This is not proof that none exists in other services/private repos.
- `#185` / merged PR `#186` show that a curated learner-controlled interactive is possible.
- Backlog has stale open issues despite related merged PRs; closing those requires acceptance review, not status assumptions.

## Proposed goal
**A single coherent user path:** arrive → try or resume without forced signup → select a problem → understand the statement and every symbol → see an exact small worked instance → manipulate a mathematically valid representation → connect the action to algebra, graph and code → answer an unaided probe → receive specific repair on the same model → navigate back/resume without losing state. Account linking remains optional until needed.

## Workstreams (order matters)
1. **Reconstruct journey:** inspect live behavior and existing Playwright runs; route/auth/session/navigation maps and reproducible defects. Preserve the working auth backend and learner state.
2. **Semantic substrate:** versioned concept glossary/ontology with stable concept IDs, contextual definitions of each symbol, aliases, examples, nonexamples, prerequisites, misconceptions, relations and provenance. Explicit variable binding per problem/step. Fail closed on undefined or conflicting vocabulary. No term silently changes meaning between algebra and graphics.
3. **Verified problem/decomposer contract:** `ProblemSpec → Solve/verify → Concept DAG → learning order → step + representation model → tests`. Each step carries a grounded learning goal, a beginner-readable statement, inputs/outputs, an instance, invariant, exact algebra, an allowed diagram/game interaction, a probe and validation status. No ungrounded diagram invention or hidden answer leakage; private holdout vs golden is a release gate.
4. **v2 journey + player, isolated from the old UI:** focus on one excellent vertical slice (Big O) anchored in #185 interactive and real-world user feedback, then Two Sum, sliding window and a HESI fraction problem. One primary action at a time; explicit 'what does this mean?', consistent navigation, game-first where teaching warrants it; responsive widths and visible progress.
5. **AI policy and evaluator:** models draft and explain within the grounded semantic model; do not invent problem facts, change mastery, or regenerate inconsistent charts. Record hallucination, missing bridge/definition, answer leakage, representational mismatch, confusion recovery, latency and fallback. Deterministic tests plus learner-visible replay are mandatory.
6. **Backlog hygiene:** dedupe and link old tickets; verify acceptance and merged PRs before closing; keep genuine product defects and owner decisions visible. Lower priority than end-to-end learning correctness.

## Release constraints
- V2 is separate route/feature flag with a rollback; do not replace main/live in one big-bang push.
- Preserve golden transcripts, canonical schemas/provenance, validated exercises, learner data, controller authority, auth/security, Big O exemplar, regression/mutation/evaluation tests.
- No automatic takeover from ACS/agents; `docs/AUTHORITY.md` governs. ACS PR #203 is separate.
- First gate: demonstrate a complete novice session on desktop and mobile with screenshots + deterministic tests, one term-to-equation-to-graph-to-game invariant check, and measured feedback; do not declare success on CI alone.
- After proving a representative vertical slice against existing product, decide whether to migrate the remaining frontend or replace it in stages.
- No silent data migration; privacy and account/session state must remain compatible and reversible.

**Discovery during v2 implementation (important source-of-truth correction, 2026-10-08 ET):** The existing companion repo [Pukujan/study-os-pedagogical-IR](https://github.com/Pukujan/study-os-pedagogical-IR/tree/43599ff8ed75bd7ceeab980d078e3a2570c7725d) already owns experimental source-backed PIR semantics. In particular `src/study_os_pir/language.py` implements `LexicalRegister` and `validate_lexical_register` (allowed/forbidden terms and assignment identifiers), with fixtures enforcing beginner `number`/`box` vocabulary and preserving `S[i]` rather than conflicting `window_sum` names. `reviews/sep4/semantic-ledger.v0.json` lists 36 source-grounded events, including terminology drift. This is **not** yet a production ontology; the PIR README and SDD explicitly say full replay, automatic raw-problem decomposition, and promotion of lexical state into canonical PIR are unproven. Independent evaluator [study-os-benchmarker](https://github.com/Pukujan/study-os-benchmarker/tree/d438988fda12e9df902caabbcb6a639834452d5d) provides `MISSING_CONCEPT`, `ORDERING_VIOLATION`, `MISSING_REPRESENTATION` and related rejection codes.

**Architectural update:** v2 should integrate pinned PIR via a reviewed Study-os adapter and evaluate with the independently pinned benchmarker, not create a second authoritative ontology/trajectory engine in the frontend. The tiny Big O preview glossary/arithmetical model is an experimental UI fixture and must not be promoted as canonical PIR. Next gate: prove an adapter can consume renderer-safe PIR turn contracts and source-backed lexical constraints without leaking assessment answers or changing the canonical semantic path. This discovery supersedes any implication in the original PR #205 proposal that these methods need to be invented anew.
