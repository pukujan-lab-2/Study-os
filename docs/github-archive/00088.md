# Issue #88: [WebApp] Learner memory: evaluation-scoped learner model (structured records plus a learner.md projection)

- State: open
- Opened by Pukujan on 2026-09-24
- Original: https://github.com/Pukujan-lab/Study-os/issues/88
- Labels: enhancement

## Why this matters
The tutor needs continuity (what this learner gets wrong, which representations helped, what is due for review). The memory must never become a dossier.

## Outcome
Typed memory records, allowlisted: capability state per skill, misconception hypotheses, representation/operation outcomes, retention schedule, and learning pace preferences. Each record carries provenance event ids, evidence class, and confidence. `learner.md` is a read-only rendered projection. The LLM may only propose memory writes. A deterministic validator commits them, with a kind allowlist, an off-scope/PII filter, and a ban on self-report-as-mastery.

## Acceptance criteria
- [ ] Off-scope proposals (health, family, location, names, feelings not tied to a learning event) are rejected. A property test uses generated adversarial proposals.
- [ ] Every memory record resolves to at least one stored learning event.
- [ ] A learner can view and delete their memory. Deletion leaves the raw learning events intact, because memory is derived.
