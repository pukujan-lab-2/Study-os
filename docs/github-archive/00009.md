## Summary

Adds a durable audit of the Study OS learner model and curriculum after the persistence/cross-chat path became operational.

The audit distinguishes:

- capabilities already promised by durable research/design docs;
- what the current v0.1 semantic runtime actually records and projects;
- learner-state signals that are only free-form or missing;
- the current lack of instantiated durable course content;
- external evidence from learning science, intelligent tutoring, programming education, and CS2023;
- a staged P2 roadmap that prioritizes instrumentation and curriculum structure over another infrastructure rewrite.

Key conclusions:

1. Many desired dimensions (assistance, multidimensional capability, transfer, retention, representation effects, self-report) are already in the design, but are not consistently operationalized in the live API.
2. Attempt chains, hint dependency, interaction mode, standardized timing/fluency, empirical error-pattern tracking, confidence calibration, and complete retention-probe lifecycle remain material gaps.
3. The checkpoint schema/design is richer than current `status`/`resume` projections.
4. `domains/dsa/sliding-window/` is still mostly a planned course tree rather than instantiated versioned lessons/problems/assessments.
5. P2 should start with a versioned telemetry/instrumentation contract, then richer learner-state projection, then a durable T1 competency/prerequisite map and real lesson/problem artifacts, before adding sophisticated statistical knowledge tracing.

This PR is documentation/research only. It does not broaden the active R0 research claim or change the database/MCP contract.
