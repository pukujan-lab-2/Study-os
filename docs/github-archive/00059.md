## Incident diagnosis — 2026-09-03

Local Luna audited the actual live WSL Study OS runtime without modifying learner data.

Classification: **B + C**.

### B — identity/runtime mismatch not evidenced

The live durable database contains no learner message/source-turn evidence attributable to the reported fresh GPT chat. The actual GPT subject/runtime identity is therefore not yet proven.

### C — historical source capture missing

Historical `default` and `subject-001` sessions contain structured learner data such as attempts/events/checkpoints, but **zero durable messages and zero raw transcript artifacts**. The only session with `messages + raw_artifacts` is a synthetic source-turn smoke subject created during transport verification.

This means the screenshot showing “no accepted checkpoint” is not evidence of database corruption. It exposes two distinct gaps:

1. historical source turns were never captured and require reconciliation/backfill where a private transcript source exists;
2. fresh-chat continuity still depends on accepted checkpoint state and cannot reconstruct bounded context from durable evidence when the checkpoint is absent/stale.

## Confirmed current resume limitation

`resume(subject_id)` reads `subject_current_checkpoint` and fails with `not_found` when a subject has no accepted checkpoint. It does not use durable messages/raw artifacts/events/attempts as a continuity fallback.

The synthetic smoke subject proves source turns can exist durably while `resume()` still cannot resume the learner.

## Required invariant

> A fresh learner-facing Study OS conversation must recover the latest trustworthy learning context from durable evidence even when no current checkpoint exists, while keeping transcript evidence distinct from assessed capability/mastery.

## Required continuity semantics

```text
stable subject identity
        ↓
resume_learning_context
        ↓
accepted checkpoint?
   yes /         \ no
      ↓           ↓
 checkpoint   durable sessions/messages/events/attempts
      \           /
       \         /
        bounded evidence-backed continuity
```

If a checkpoint exists and newer evidence exists, return both explicitly:

```text
accepted checkpoint
+ post-checkpoint evidence
→ continuity response with provenance boundaries
```

Do not silently promote transcript/source evidence into mastery or capability state.
