### Note on local `preflight` and two pre-existing failures

This checkout is a linked worktree of `D:/claude/Study-os` and the machine has additional registered worktrees (`study-os-s1`..`s4`) outside the canonical root, so `.continuity/config.json`'s `workspace.mode: managed-worktrees` reports them and `preflight` returns `INVALID_TARGET` locally. This is pre-existing and pin-independent: the same five errors appear at the old `0b3be9c` pin. In a single-checkout copy of this tree (the shape CI uses, where `git worktree list` has one entry) both pins return `MODE: TARGET_VALID`, so the bump is neutral for the validator.

Two unrelated tests fail on this Windows checkout at the base commit too, both from the same CRLF artifact: `tools/check_pir_mutation_results.py::git_blob_sha` hashes raw working-tree bytes (CRLF here) while the audited blobs are LF, so `tests/test_pir_mutation_gate_contract.py` reports changed audited sources for `src/study_os/pir/{contracts,controller}.py` and `src/study_os/services/pir_runtime.py`. Those files are untouched by this PR and match their committed blobs (`git hash-object` == committed SHA).
