Refs #27 and #21.

Bounded F0 runtime-compatibility slice. The package currently declares `requires-python >=3.11` while the main validation job runs on 3.12. This adds a separate Python 3.11 compatibility job that:
- installs the same validation dependencies;
- compiles runtime/tools/tests;
- builds the wheel;
- installs and smoke-tests the built wheel in an isolated 3.11 virtualenv;
- runs the full unittest/Hypothesis suite under Python 3.11.

The existing Python 3.12 validation remains the authoritative lint/type/coverage gate, so this avoids widening unrelated tooling in the same slice.

No runtime semantics, schema, MCP contract/tool count, HTTP/frontend, deployment, secrets, or adaptive authority change.

Acceptance: both the existing 3.12 validation job and new 3.11 compatibility job must be green on the exact head before merge.
