## Summary

Refs #26, #21, #10.

Continues E11a-2 by migrating only `record_assessment` onto the canonical transport-independent application boundary while preserving the P2 retention-probe completion semantics already reachable through the MCP fallback.

### Scope

- adds canonical `RecordAssessmentRequest` / `RecordAssessmentResult` registration and public exports;
- formalizes existing optional `retention_probe_id` as an explicit application-contract extension without changing the MCP required-input list;
- adds the runtime-port/application-service bridge and MCP result projection;
- routes the existing MCP `record_assessment` tool explicitly through the application boundary;
- preserves additive `retention_probe_id` / `retention_probe_status=completed` response fields only when a probe is actually completed;
- rejects application-only version metadata and unrelated unknown MCP fields;
- adds contract/schema/public-surface and direct-runtime/application/MCP differential conformance.

### Preserved invariants

- exact 13-tool MCP semantic surface remains unchanged;
- the seven established MCP assessment fields remain required and `retention_probe_id` remains optional;
- idempotency continues to include the normalized optional probe linkage;
- session and evidence remain subject-scoped;
- linked assessments validate scheduled probe existence, subject, status, and capability/concept match;
- assessment insertion and probe completion remain atomic;
- exact retries reuse the stored assessment/probe-completion result;
- no DB schema, adaptive authority, HTTP/frontend, deployment/private credentials, or learner-semantic change is included.

### Negative / retry coverage

- changed request under the same idempotency key conflicts;
- missing probe fails `not_found`;
- wrong-subject or capability-mismatched probe fails `integrity_error` without inserting an assessment;
- an already-completed probe cannot be closed by a second assessment;
- malformed runtime completion output fails closed at the application boundary;
- application-only/unknown MCP fields fail validation.
