## What changes

The shipped sliding-window PIR lesson (`sliding-window.max-sum-k.sep4.v1`) is now generated from the two goldens in `domains/dsa/sliding-window/golden/`, step by step, and stops where they stop (`enumerate(a)` and `append`).

| Golden step | Concept | Probes on the all-correct path |
|---|---|---|
| G1 step 0 | problem and `a` | none (explain) |
| G1 step 1 | position `p` | position of 6 → 4; of 1 → 5 |
| G1 step 2 | index `i = p - 1` | index of 6 → 3; of 9 → 5 |
| G1 step 3 | box size `k` | `k = 5`; `k = 2` (box contents) |
| G1 step 4 | `i` moves the box | `i = 1, k = 2`; `i = 3, k = 2` |
| G1 step 5 | `sum[i]` | `sum[i=2]` with the box shown → 9; without the box, `k = 2` → 8 (`2 6` is partial) |
| G2 step 1 | successive sums | `sum[i+1]` → 14, `sum[i+2]` → 8, `sum[i+3]` → 14 |
| G2 step 2 | recurrence repeated from `S[0]` (`j = k - 1`) | `S[1]` → 14; `S[2]` → 8 |
| G2 step 3 | `enumerate(a)` | `a = 6` → (3, 6); `a = 8` on a changed array → (2, 8) |
| G2 step 4 | `S[i] = ...` → `S.append(...)` | two conversions |
| boundary | `frontier.assembled` | exit `assembled_mastery_unproven` |

Every concept follows the golden feedback graph:

- After a correct answer, the lesson shows why on the same chart.
- After a wrong answer, it shows the right answer on the chart and says "It’s okay, let’s keep trying." Then it retries on a different example and asks one more check before advancing.
- After a partial answer, it keeps the correct part and asks only for the missing step (`2 6` → `2 + 6 = ?`; value-only append → storage only).

The controller keeps no counters, so step ids carry them: `<concept>.e<example>.n<correct answers still needed>`. That gives 326 generated steps, with 19 probes on the all-correct path. Before this change the lesson had 20 hand-written steps: `problem_anchor`, `sum_probe`, `sum_partial`, `arithmetic_probe`, `sum_wrong`, `recurrence_*`, `enumerate_*`, `append_*`, `max_*`, `first_window`, `boundary`, `final_loop`.

## Judgment calls

- **Enumerate has no box.** The golden's enumerate chart and the benchmarker `enumerate-vertical` fixtures forbid `window_box` and the pair row in enumerate exercises. The box chart (numbers, index row, box, `k`) is required in every recurrence and append step.
- **Old runs stop at the revision check.** Runs pinned to v1 fail closed on the existing revision check, so they get an integrity error instead of being routed through new step ids. An in-progress v1 run has to be restarted.
- **"Are you ready?" is not asked.** Golden 1 step 0 asks it, but it is shown as the explain step before position, because the controller has no readiness probe.
- **The short append answer is not accepted.** Golden 2 rule 12 allows accepting `S.append(...)` when the intent is clear. Intent cannot be judged deterministically, so that answer is treated as incorrect and the full answer is shown. A value-only answer counts as partial.
- **Examples repeat after many misses.** After three or more errors, the example bank cycles.
