# Issue #82: [WebApp] Epic: hosted Study OS web app (study.design-bakery.com, all on gravebuster)

- State: open
- Opened by Pukujan on 2026-09-24
- Original: https://github.com/Pukujan-lab/Study-os/issues/82
- Labels: enhancement

## Why this matters

Study OS works today as a local, GPT-surfaced tutor for one learner. Alex wants it as a hosted web app that two real learners can use every day: Alex (DSA) and a second learner (any subject, currently the HESI nursing exam). Everyday use becomes product data, but only learning and UX data, never personal data.

## Outcome

- **D018 (owner amendment, 2026-09-24):** everything is self-hosted on Alex's Linux machine `gravebuster` at `https://study.design-bakery.com` — the built React frontend at `/` and the API at `/api` on the same origin (first-party cookies), with Postgres, all behind a Cloudflare named tunnel created through the Cloudflare API. No Vercel.
- Accounts: Google sign-in (primary) with open signup, plus a local email/passphrase (argon2id) fallback. Minimal profile only (Google subject, email, display name, learner handle), kept in `auth.*`; learning data stays keyed by a pseudonymous `subject_id`.
- An LLM tutor that uses cheap IRE/InferHub inference. It only acts under the deterministic controller (ADR-0016 / PIR runtime), with explicit success and failure conditions.
- A learner memory scoped to evaluation and learning only.
- Agent-vs-agent tests that check tutor behavior automatically and cheaply.
- Analytics over learning and UX signals: first-party event tracker into Postgres plus Metabase-ready SQL views. **No PostHog** (D018).

## Scope

The spec and research are in `docs/webapp/` (spec PR for SOS-0003). Child issues form the issue log. Each child is implemented on its own `task/SOS-XXXX-*` branch with a PCM task file.
