## Problem and intended direction

The pinned PCM validator (CLI 0.6.0) warns that this repository's `AGENTS.md` carries no **issue-log-format policy marker**, and three finished or superseded worktrees sat outside the layout the continuity protocol permits. Both are small, mechanical, and currently only half-done: the fixes exist in the working tree of `main`, which this repository's contract does not allow me to commit to directly. This issue exists so the change can land through a reviewed branch.

## What is affected

Anyone running the pinned `continuity validate --root .`: before this work it reports `INVALID: 3 error(s)` (worktrees outside the canonical checkout) plus the marker warning, so a genuine future violation would be lost in known noise.

## Interpretation (inferred)

The marker warning is not a defect in this repository's writing style; it is a new 0.6.0-era check that adopters must satisfy explicitly. The severity contract makes a *missing* marker a warning precisely so existing adopters stay valid, so this was safe to land on its own schedule rather than blocking the pin.

| Test | Cause |

| `test_pir_golden_conformance.test_oracle_pins_goldens_and_benchmarker` | `core.autocrlf=true` rewrites LF→CRLF in the working tree; the test hashes raw working-tree bytes, so it sees `65ca6cde…` where the pinned LF hash is `87ee6091…` |
| `test_pir_mutation_gate_contract.test_checker_accepts_audited_equivalent_survivor` | same cause; `tools/check_pir_mutation_results.py` computes a git blob SHA over working-tree bytes and sees the CRLF variant |

For the first two, normalizing CRLF→LF reproduces the pinned hashes exactly, and `git status` shows the files unmodified — so the gates are correct and the local checkout's line endings are the variable. These belong in their own issue.
