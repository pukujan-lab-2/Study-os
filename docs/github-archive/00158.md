Refs #126

## Isolation approach

**Open Shadow DOM** (preferred) + **CSS modules** injected into the shadow root.

| Layer | Role |
| --- | --- |
| Shadow DOM | True isolation — document `table` / `pre` / flex rules do not pierce |
| `TeachRenderBox.module.css` | Island-owned compact layout |
| Light-DOM fallback | SSR / no-`attachShadow` → `data-isolation="css-module"` |

Host: `data-testid="teach-render-box"`, `data-teach-render=<kind>`, `data-isolation=shadow-dom\|css-module`.

## Frame / render types

Builtins: `code_block`, `mermaid` (alias of `mermaid_flow`), `growth_workers`, `growth_curve`, `growth_table` (compact **inside** island), plus existing `fraction_bar` / `box_index` / `code_tree`.

## How new render types register

```ts
import { registerTeachRender } from "./TeachRenderBox";

registerTeachRender({
  types: ["my_kind"],
  describe: (frame) => "...",
  render: (frame) => <MyView frame={frame} />,
});
```

Then add the Frame union member in `web/src/api.ts`. `Frame.tsx` always dispatches through the island.

Ops: `docs/ops/TEACH_RENDER_BOX.md`

## Explain again / Worked example

- **Explain again** → `adapt(reexplain)` picks alternate authored indices so the **frame type changes** (Big O `growth_workers` ↔ `growth_curve`). Tutor regenerate is fallback.
- **Worked example** → authored `worked_example` / `_alt` (or explain-frame pool) with a different type than teach.
