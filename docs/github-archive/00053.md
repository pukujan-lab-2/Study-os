## Architectural position

Preserve as durable assets:

- architecture and ownership boundaries;
- persistent data semantics/migrations;
- raw evidence integrity/provenance;
- learner/system evaluation contracts;
- curriculum/task provenance;
- representation/intervention semantics;
- PDD/SDD/invariants and recovery guarantees.

Implementation code is replaceable. Engineering assurance is risk-driven and exists to protect these durable assets and current product failures rather than being the product objective itself.

## Highest-priority invariant

> No silent learner-evidence loss.

Real HTTP 502 failures during GPT learning are treated as a data-integrity/reliability incident. An interaction must be durably acknowledged locally or explicitly identifiable as missing/uncertain and recoverable through reconciliation/backfill.

## Historical issue cleanup

This PR deliberately does **not** close or rewrite historical issues. It records proposed dispositions only. Issue cleanup should be a separate reviewed action after this roadmap is accepted.

## Boundary

Planning/decision documentation only.

No runtime code, SQLite schema, MCP contract, frontend, deployment, adaptive authority, local secrets/configuration, or learner data is changed by this PR.
