# Issue #89: [WebApp] LLM interpreter via IRE/InferHub: route policy, client, validation, telemetry

- State: open
- Opened by Pukujan on 2026-09-24
- Original: https://github.com/Pukujan-lab/Study-os/issues/89
- Labels: enhancement

## Why this matters
Cheap inference lets the app scale. The LLM is only an interpreter:
- grading free-text answers;
- diagnosing misconceptions;
- rewriting a step that failed for this learner.

Deterministic PIR steps are served with no LLM call.

## Outcome
An OpenAI-compatible streaming client to `https://api.inferhub.dev/v1`:
- primary route `cb/glm-5.3`, fallback `cb/deepseek-v4.1-flash`, with per-operation route config;
- tool/JSON-schema outputs;
- a validator in front of every output, with a deterministic fallback;
- prompt-free telemetry (route, tokens, cost, latency, validation result);
- the key comes from the gravebuster secret store (env file with mode 600), never from the repo.

## Acceptance criteria
- [ ] Output that fails validation is never shown to a learner. After one repair retry, the canonical step is served instead.
- [ ] The route, model, price snapshot id, and cost are recorded per interpretation. A monthly spend cap is enforced, and an alert fires at 80%.
- [ ] Route changes are versioned module changes, never silent drift.
