# Issue #90: [WebApp] Web session controller: deterministic state machine with explicit success and failure conditions

- State: open
- Opened by Pukujan on 2026-09-24
- Original: https://github.com/Pukujan-lab/Study-os/issues/90
- Labels: enhancement

## Why this matters
ADR-0016: code owns progression, assistance ceiling, fade, and mastery gates. The web session needs its own state machine around PIR problem runs, covering warm-up review, lessons, checks, and summary.

## Outcome
A pure-function controller `(state, event, module_versions) -> (state', effects)` with these states:
- `START`, `REVIEW_DUE`, `PRESENT_STEP`, `AWAIT_ATTEMPT`, `INTERPRET`, `FEEDBACK`, `RETRY_DIFFERENT`, `CHECK`, `ADVANCE`, `FADE`;
- exits `PAUSED`, `SESSION_DONE`, `BLOCKED`.

It enforces the golden teaching rules and the capability states (`not_tested` … `pass_delayed`).

## Acceptance criteria
- [ ] Deterministic: the same inputs and versions produce the same outputs (property test).
- [ ] Mastery requires unaided + transfer + delayed + 2 unseen items. There is no code path to `mastered` without that evidence.
- [ ] An incorrect answer always routes to correction, then a different example, then one more check before advancing (model-based test).
- [ ] Every LLM effect passes controller validation before it becomes learner-visible.
