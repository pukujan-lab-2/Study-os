## What

`sliding-window-box.v1` (the first DSA lesson) now ships real multi-representation frames, so chat `regenerate_presentation` / Explain again changes the picture instead of being a visual no-op.

- All 6 steps (`problem`, `position`, `index`, `box-size`, `box-start`, `window-sum`) keep their existing `box_index` geometry frames and gain authored `code_block` (algebra) and/or `mermaid_flow` frames after them.
- Each step gains a `teach_visual_v1` block: `default_frame_indices` = the existing geometry frames (today's default picture is byte-identical), `explain_frame_indices` = the appended frames.
- No engine change: `teach_visual.alternate_indices()` already rotates to `explain_frame_indices`, so Explain again now returns frames that differ from the card on screen.

## Follow-up commit (`4a53888`) — CI and review caught two real problems

1. **Answer leak in the new cards.** A step's teach card and its probe are on screen together, and the probe's accepted answers are forbidden content while it is open. The first version of the `position`, `box-start` and `window-sum` alternate cards stated the answer to the probe on that same step (`p = 4` for number 6, `a[1:4] = [7, 2, 6]`, `window_sum(2) = 9`). They now teach the same idea with answer-free examples: position 3 / number 2 (matching the step's existing default frame), a symbolic slice, and `window_sum(0)`.
2. **Three DB-backed API tests pinned the old no-op.** `tests/test_web_player_api.py::PlayerRegeneratePresentationTests` asserted that a refused/absent proposal leaves `regenerate_presentation` as `None` on this lesson. The engine contract (`tutor._resolve_render`, `presentation.authored_reserve`) is that a refused or absent proposal falls back to the step's authored card, and it was withheld before *only* because this lesson's authored card was identical to the card on screen — i.e. because of the very no-op this task removes. Those tests now assert what matters: the refused model card is never adopted, the step/probe do not advance, the served frames are the authored alternate, and `ANSWER_REVEAL_FORBIDDEN` / `INVALID_PRESENTATION` plus `RENDER_AUTHORED_RESERVE` are recorded in `learn.llm_interaction.validation_codes`.
