## Current interactive v2 slice (owner feedback incorporated)
- The **computer assigns the rule** through an authored five-mission progression: three-box linear, four-box linear, three-box all-ordered-pairs, four-box ordered-pairs, and four-box first-only. Learners cannot pick an asymptotic complexity class.
- Learner performs each mission using **native drag-and-drop** or the tap/keyboard fallback: select a stick, tap or drag to a box or ordered-pair tile. Invalid and duplicate moves receive **immediate feedback** and do not advance the board. The board, not a detached numeric answer field, is the assessment.
- The **side-by-side SVG graph grows on each accepted placement**. Partial progress is labelled *work done so far*, not a completed complexity measurement. Points/lines from prior missions represent finished boards only. The exact game equation and Big O name are revealed **after** successful completion of that board.
- A learner can go to the overview and return without the board and graph diverging. Finite tasks preserve state in the component; an explicit reset clears it. No results are saved to backend and the demonstration is not proof of mastery.
- No fictitious O(log n) or O(n log n) visuals. These require a different grounded algorithm/interaction model and are not implemented.
- Existing approved #185 sticks-and-boxes module is retained for legacy lessons and is not changed by the new v2 game. PIN-backed PIR/lexical work from study-os-pedagogical-IR and independent benchmarker remain separate future integration, not replaced by frontend text strings.
