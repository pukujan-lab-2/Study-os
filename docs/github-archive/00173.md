## What changed

**`web/src/mascot/locomotion.ts`** (new) — the frozen interface the RED tests already import. Pure reducer: no timers, no wall clock, no DOM.
- Facing flips **only** on `turnDone`, so a direction request routes through the turn one-shot instead of snapping mid-stride (M-P3).
- The walk cycle advances by **distance travelled**, not elapsed time — that is how a walk cycle should read (feet planted while the body glides), and it keeps `frame` monotonic instead of free-running on a wall clock.
- Timed phases complete from `tick` alone; early `turnDone`/`oneShotEnd` are still accepted and idempotent.

**`web/src/mascot/Sprite.tsx`** — was single-row only, which cannot express these sheets:
- `cols` for multi-row grids (walk 3x2 = 432x352, turn 2x2 = 288x352)
- explicit `frame` for FSM-driven poses (CSS keyframes can only walk one axis)
- `mirrored`, since the sheets are authored facing right

**`web/src/mascot/Pet.tsx`** — the actual bug:
- removes the 4.5s CSS transform transition that **slid** the pet between two points while the idle sheet played. That is the "shaking in place" Alex reported. The FSM owns motion now and the container carries no transition.
- rAF loop drives `tick`; `dt` clamped to 64ms so a backgrounded tab cannot fast-forward a whole walk in one frame
- exposes `data-pet-activity` / `data-pet-facing` for e2e assertions

Plus the S4 assets/schema already on the branch: `schemas/mascot-sprite-manifest.v1.schema.json`, `tools/generate_mascot_frames.py`, `web/public/mascot/manifest.json` + hash-verified `pet-walk.webp` / `pet-turn.webp`, `tests/test_mascot_manifest.py`.
