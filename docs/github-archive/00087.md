# Issue #87: [WebApp] Database and data model: Postgres on gravebuster, with append-only learning and UX events

- State: open
- Opened by Pukujan on 2026-09-24
- Original: https://github.com/Pukujan-lab/Study-os/issues/87
- Labels: enhancement

## Why this matters
Learning evidence must be durable, append-only, attributable to module versions, and analyzable. The existing SQLite runtime is single-user and local.

## Outcome
Postgres 16 in Docker on gravebuster, with migrations. Schemas:
- `auth`;
- `learn` (subjects, skills, items, sessions, problem runs, turns, attempts, capability-state transitions, LLM interpretations, graph-promotion candidates);
- `ux` (reactions, timing, abandon events);
- `memory`;
- `analytics` (read-only views).

Nightly `pg_dump` with restore drills. The data semantics mirror `docs/DATABASE_CONTRACT.md`.

## Acceptance criteria
- [ ] Event tables are append-only, enforced by grants plus a trigger that rejects UPDATE/DELETE, and tested.
- [ ] Every learning event carries evidence class (observed / self_reported / derived), assistance level A0–A6, and the module version set.
- [ ] A backup and restore round trip is verified by a script.
- [ ] An analytics role has SELECT only on `analytics.*`.
