# Issue #98: Web app: self-hosted session replay with rrweb (opt-in, masked, retention-limited)

- State: open
- Opened by Pukujan on 2026-09-24
- Original: https://github.com/Pukujan-lab/Study-os/issues/98
- Labels: enhancement

Parent epic: #82. Refs D017 / D018 (owner amendment 2026-09-24: first-party analytics instead of PostHog).

## Goal
Self-hosted, privacy-first session replay for the Study OS web app so Alex can see where learners get stuck, using the open-source [rrweb](https://github.com/rrweb-io/rrweb) recorder (MIT).

## Scope
- Record DOM mutation/input events with `rrweb.record` in the React client, **opt-in only** (per learner setting, off by default), with a visible "recording" indicator.
- Privacy: `maskAllInputs: true`, mask all text inputs and free-text answers, `blockClass` on any element that could show personal data (account/profile pages are never recorded), no network/console capture, no canvas.
- Batch events into compressed chunks (gzip / rrweb pack) and upload via an authenticated `POST /api/replay/chunks` (same-origin, CSRF-protected, size and rate limits).
- Storage: Cloudflare R2 bucket (preferred, lifecycle rule) or a Postgres `replay.chunk` table; chunk metadata (session id, subject id, seq, byte size, created_at) in Postgres.
- Retention: default 14 days, configurable, enforced by a daily job plus an R2 lifecycle rule; learner can delete their recordings.
- Private replay page (`/admin/replay/:session`) using `rrweb-player`, admin role only, reachable only when signed in as admin.
- Link replays to the learning event log (session id / turn ids) for the drop-off view.

## Acceptance
- Recording never starts without opt-in; turning it off stops recording immediately.
- A canary string typed into any input never appears in stored chunks (test).
- Chunks older than the retention window are deleted (test).
- Non-admin requests to replay endpoints get 403 (test).
- No third-party network requests from the client (rrweb bundled).

## Out of scope for slice 1
Not built in the first slice; the first slice ships only the first-party event tracker (`POST /api/events`) and Metabase-ready SQL views.
