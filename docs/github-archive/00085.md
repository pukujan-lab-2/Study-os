# Issue #85: [WebApp] Backend API: FastAPI service that wraps the PIR runtime for web sessions

- State: open
- Opened by Pukujan on 2026-09-24
- Original: https://github.com/Pukujan-lab/Study-os/issues/85
- Labels: enhancement

## Why this matters
The web surface must reuse the existing deterministic runtime (`src/study_os/pir`, `services/pir_runtime.py`) rather than fork the pedagogy.

## Outcome
A FastAPI app (`src/study_os/web/`). Endpoints:
- `POST /sessions`, `GET /sessions/{id}`;
- `POST /sessions/{id}/responses` (attempt);
- `POST /sessions/{id}/reactions` (UX signal);
- `GET /me/progress`, `GET /subjects`.

Responses stream turns as SSE (with a heartbeat of 15 s or less). Every turn is produced by the controller. Optional LLM interpretation runs behind it.

## Acceptance criteria
- [ ] The OpenAPI schema is generated and checked in CI. Pydantic models are strict (`extra=forbid`).
- [ ] Idempotency keys on attempt submission: a replay returns the same turn and never double-records.
- [ ] No endpoint returns hidden assessment answers before an attempt is recorded (property test over all assets).
- [ ] Rate limits per account. Structured logs contain no free-text learner content.
