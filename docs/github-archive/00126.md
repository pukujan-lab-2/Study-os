## Recommendation: in-lesson chat agent lifecycle (best setup)

**Question:** cold start? stream for ~3 min then sleep? wake again on human message?

### Short answer
**Cold-start per learner turn, stream that turn, then fully idle until the next human message.** Do **not** keep a 3-minute always-on agent after the first render. Use a **per-turn wall budget** (suggest **90–180s**) for stream + tools (including InferHub re-render), then end the turn cleanly. Next message wakes a **new turn** with the same `session_id` + step context loaded from Postgres.

### Why this beats a sticky 3-min worker
- Spend: idle keep-alive burns InferHub tokens/time with no learning signal.
- Correctness: lesson state is durable in Postgres; waking with context is enough.
- Ops: gravebuster is CPU-busy; fewer long-lived processes.
- Matches IRE: request-scoped BYOK turns, drain streams, resume/next message rather than killing mid-tool.

### Recommended architecture
1. **Cold start** on first companion open *or* first chat message (lazy). No per-user daemon.
2. **Turn = one human message:**
   - Client opens **SSE / streamed** `POST /api/player/sessions/{id}/tutor` (upgrade from today’s non-stream JSON).
   - Server loads step + allowed tools: `reply`, `regenerate_presentation` (InferHub cheap route per IRE), never subscription.
   - Stream tokens; when a re-render tool completes, push an event so the **lesson card updates in place** (D4 companion).
   - Turn ends when model finishes or **turn_deadline** hits; return partial + `turn_id` for telemetry.
3. **Idle:** no process held. Soft UI may show “ready” but backend is cold.
4. **Wake:** next human message starts another turn with same session/step + prior chat turns from DB.
5. **Caps:** AI spend caps already planned; per-turn timeout + max tool calls (e.g. 1–2 regenerates per message).
6. **Optional later:** “warm pool” of InferHub connections at the *gateway* level — not a 3-min agent personality per learner.

### What exists today vs gap
- Today: `POST .../tutor` and `.../adapt` are **request/response**, not streamed multi-tool re-render.
- Needed for #126: streamed turn + `regenerate_presentation` tool + frontend apply render + 1–5 typed review (separate panel).

### Decision to lock
Unless Alex overrides: **no sticky 3-min agent**; **cold turn + stream + idle + wake on message**; turn budget **≤180s**.
