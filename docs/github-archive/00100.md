## What ships
- **Decisions**: D017 accepted, and the D018 amendment recorded (`docs/DECISIONS.md`, `docs/webapp/D018_AMENDMENT.md`).
- **Backend** (`src/study_os/web/`): FastAPI on Postgres 16.
  - Schemas: auth, learn, ux, cache, analytics. The learning, UX and decision tables are append-only.
  - Metabase-ready `analytics.v_*` views.
- **Auth**:
  - Google OIDC (state + PKCE + nonce) with open signup.
  - Local email/passphrase fallback (argon2id).
  - Server-side sessions: 30-day absolute, 7-day idle expiry.
  - CSRF protection, an origin/header guard, and login throttling with exponential backoff.
  - Per-IP and per-user rate limits.
  - Caps: global daily spend, monthly spend, and per-user daily model calls.
- **Controller**: a pure web state machine over PIR assets. It serves the SOS-0002 sliding-window asset and the compiled HESI topic assets through the same PIR controller. It also handles FSRS review warm-ups, section checkpoints, and a wheel-spinning guard.
- **HESI A2 pack v0**:
  - 38 topics, 303 original items citing OpenStax, Open RN and CDC.
  - Each item was independently reviewed by an LLM, and items where the reviewer disagreed with the answer key got a second solve.
  - 290 items are servable. All are marked `unreviewed` until Alex reviews them.
- **Decision layer**:
  - Rules first, with no model call when a rule resolves the answer.
  - Next tier: hosted Jev `typesafe/jev-1.13` (OpenRouter Decisions API), which acts only when confidence ≥ τ, plus audit sampling.
  - Final tier: InferHub `cb/glm-5.3` → `cb/deepseek-v4.1-flash` for grading and for rewriting a failed step. Output goes through a validator, gets one repair attempt, then falls back; responses are cached in Postgres.
  - Every decision is logged.
- **Frontend** (`web/`): Vite + React. Pages: login/signup, home (HESI topic graph plus DSA), lesson player and summary.
- **Tracker**: first-party, sending events to `POST /api/events`. No PostHog.
- **Evals** (`tools/run_agent_evals.py`): agent-vs-agent T0 runs with 10 personas across DSA and HESI, 13 detectors, and conformance checks via `pir/conformance.py`. There are offline tests, and a live mode behind `STUDY_OS_EVAL_LIVE=1`.
- **Deploy** (`deploy/`): Dockerfile, compose (api, postgres, cloudflared, backup), env template and README. The Cloudflare tunnel and DNS were created via the API.
