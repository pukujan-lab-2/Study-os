# Issue #66: [P4/PIR] Integrate canonical PIR tutoring into Study OS GPT/MCP

- State: open
- Opened by Pukujan on 2026-09-06
- Original: https://github.com/Pukujan-lab/Study-os/issues/66

## Purpose

Make the existing Study OS GPT the first real learner-facing runtime for the validated Pedagogical IR work.

This issue is the executable acceptance ledger for the first product integration slice. It is subordinate to #63 (deterministic learning controller/product tracker) and consumes the PIR/evidence work tracked in #65.

The first slice is intentionally narrow:

> Open the existing Study OS GPT, give it the known September-4 sliding-window problem, and traverse a validated canonical PIR through the existing Study OS MCP with deterministic progression, renderer-safe turns, durable evidence, and no unsupported mastery claim.

## Architecture under test

```text
Study OS GPT
    ↓ semantic/tool calls
existing Study OS MCP
    ↓
ApplicationService
    ↓
known canonical sliding-window PIR
    ↓
deterministic traversal/controller
    ↓
renderer-safe TeachingTurn
    ↓
GPT displays authorized learner-visible content
    ↓
learner response
    ↓
deterministic assessment / bounded interpretation
    ↓
next canonical state
```

GPT remains continuously present for conversation and semantic interpretation, but backend code/state owns canonical graph identity, current node, legal transitions, assessment truth where deterministic grading is available, representation requirements, answer exposure, and mastery/progression claims.

## Explicit non-goals for this slice

- arbitrary raw-problem → PIR compilation in the live GPT;
- broad DSA curriculum generation;
- auth/tenant redesign;
- new frontend;
- Luna as a production runtime dependency;
- learner-profile redesign;
- population-level learning-efficacy claims;
- new infrastructure unrelated to the first usable PIR teaching run.

## Proposed MCP/application operations

Final names are frozen by SDD, but the first slice should expose a small semantic surface equivalent to:

- `resolve_problem`
- `start_problem`
- `get_problem_turn`
- `submit_problem_response`
- `request_problem_expansion`

Existing session/evidence tools remain authoritative and must not be duplicated.

## Non-negotiable invariants

1. Known canonical PIR identity/version is explicit and immutable for a problem run.
2. Learner state/personalization changes traversal, not canonical problem structure.
3. GPT cannot advance to an unauthorized canonical node.
4. GPT cannot convert self-report or lesson completion into mastery.
5. Controller-only expected answers never appear in renderer-safe output.
6. Frozen/parameterized representation state cannot silently drift across a required bridge.
7. Correct learner work survives correction; repairs change only what is authorized.
8. Historical PARTIAL outcomes remain distinct from INCORRECT.
9. Existing Study OS evidence/session durability semantics remain intact.
10. Restart/resume preserves problem-run identity and authorized next state.
11. Existing MCP tools remain contract-compatible.
12. Local/private evidence and hidden benchmark material never enter public renderer output.
13. Implementation failures fail closed rather than producing successful-looking tutoring state.
14. Luna/local deployment may fix environment/integration issues but may not weaken contracts/tests or redesign pedagogy to obtain green results.
