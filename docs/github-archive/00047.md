## Summary

Refs #26, #21, #10.

Continues E11a-2 by migrating only `schedule_retention_probe` onto the canonical transport-independent application boundary.

### Scope

- adds canonical `ScheduleRetentionProbeRequest` / `ScheduleRetentionProbeResult` registration and public exports;
- adds the runtime-port/application-service bridge and MCP result projection;
- routes the existing MCP `schedule_retention_probe` tool explicitly through the application boundary;
- rejects application-only version metadata and unknown MCP fields rather than allowing them to reach the runtime;
- adds contract/schema/public-surface tests;
- adds direct-runtime/application/MCP differential conformance over an evidence-backed checkpoint and durable retention row.

### Preserved invariants

- `due_at` remains the existing opaque non-empty string and is not converted to a datetime;
- runtime lexical persistence/order of `due_at` remains unchanged;
- source checkpoint must exist and belong to the same subject;
- concept insertion remains on demand;
- idempotency request fingerprint remains `{subject_id, concept_id, due_at, source_checkpoint_id}`;
- `get_next_probe` projection is differentially checked against the direct runtime;
- exact 13-tool MCP semantic surface remains unchanged.

### Negative / retry coverage

- exact retry returns the same durable probe with `created=false`;
- changed request under the same idempotency key conflicts;
- missing source checkpoint fails `not_found`;
- wrong-subject source checkpoint fails `integrity_error`;
- malformed runtime result fails closed at the application boundary;
- application-only/unknown MCP fields fail validation.

No DB schema, HTTP/frontend, deployment/private credentials, adaptive authority, or learner-semantic change is included.
