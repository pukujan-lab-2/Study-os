## Adds

- `propose_fsrs_review_update`
  - requires maintenance phase
  - requires an explicit canonical source assessment ID
  - requires explicit `again|hard|good|easy`; does not guess FSRS rating from generic pass/fail
  - computes retrievability-before, updated FSRS card state, review log, and next due time
  - returns only a shadow `DecisionProposal`
- `propose_fsrs_maintenance`
  - only ranks already-reviewed, currently due card states
  - hard-excludes unreviewed/not-due concepts
  - ranks due concepts by `retention_urgency * goal_relevance`
- deterministic replay by disabling FSRS interval fuzzing
- stable Study OS-derived FSRS card IDs
- upstream donor-reproduction test using py-fsrs's documented no-fuzz repeated-Good interval sequence
- tests for UTC enforcement, explicit rating semantics, canonical evidence linkage, serialized donor state, and due-only maintenance selection

## Architecture boundary

- FSRS does not access SQLite/checkpoints directly
- FSRS does not infer mastery
- FSRS does not choose probe content or grade probes
- FSRS does not close retention probes yet
- FSRS donor state remains derived until a canonical retention projection is separately approved
- no public semantic tool is added
