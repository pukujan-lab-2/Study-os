**Pukujan commented, 2026-09-07**

Representation-gap finding from Luna-vs-Sol calibration: treat missing visual/diagram output as a semantic representation failure when the learner state or representation intent requires a visual family, not as a stylistic difference. The historical sliding-window golden explicitly requires keeping the same chart/diagram through explanation/exercise/correction and preferring visual equivalence over prose; the current deployed PIR runtime, however, only enforces learner_visible_markdown + named visible_components and does not generically require an actual chart/diagram family for unfamiliar-problem adaptation. Differential scoring should therefore include: (1) required representation family selected, (2) required semantic roles/relationships visible, (3) visual continuity across probe/correction, (4) no unnecessary fallback to code/prose when visual representation is authorized/required, and (5) renderer capability actually realizes the required family. This should become an executable representation-intent invariant in the post-PAM-C prerequisite/representation slice rather than a prompt-style preference.

**Pukujan commented, 2026-09-07**

Architecture clarification added in commit `9239bd849214e3e8cb79ac013afeed1262a07a3c`: `docs/P4_AUTOMATED_DATASET_SHAPED_PEDAGOGY_PIPELINE.md`.

This restores the original Study OS direction that recent reactive failure analysis under-emphasized:

- the learner should **not** remain the runtime pedagogy debugger;
- use an automated author/compiler to produce a **dataset-shaped** competency/prerequisite/problem-step/scaffold plan;
- use a deterministic executor to select the exact next pedagogical action;
- emit a typed `TargetedTurnSpec` fixing the active relation, representation family/mode, required semantic roles, answer-cue policy, information budget, exercise target, progression permissions, and hidden/forbidden content;
- Luna/Sol only realize that bounded turn; they do not rediscover decomposition/progression every turn;
- validate the realized output before learner exposure; regenerate/fallback/model-escalate only after contract failure;
- build automated authoring/evaluation now in shadow/offline mode while preserving the existing gate against arbitrary **unreviewed live** raw-problem compilation.

This aligns with the existing OSS donor audit: Oppia/OATutor-style atomic competencies + problem→step→KC/scaffold structure, ScaffoldLM-style ordered intermediate targets, constrained LLM generation behind validation, and offline reproduction before live promotion.

The September-4 transcript is therefore a regression corpus for the compiler/contracts/validator—not a procedure requiring the learner to keep correcting the tutor.
