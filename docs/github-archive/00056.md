# Issue #56: [P3.0] Add append-only learner transcript/source capture and outage reconciliation

- State: closed (2026-09-24)
- Opened by Pukujan on 2026-09-03
- Original: https://github.com/Pukujan-lab/Study-os/issues/56

## Parent

Refs #52.

## Why this issue exists

A reviewed 2026-09-03 Study OS learning session exposed a durability gap after MCP recovery:

- real learning continued while the Study OS MCP path was returning 502s;
- after recovery, the structured/canonical learner state was reported materially stale relative to the conversation;
- the learner-facing semantic surface did not expose an append-only transcript/source-turn primitive;
- structured writes becoming healthy again did not recover the verbatim interaction history needed to reconstruct the missing learning sequence.

Public-safe problem-discovery evidence is being added under:

`/sessions/2026-09-03/mcp-recovery-transcript-gap/knowledge/problem-discovery.md`

The verbatim private conversation is **not** committed publicly.

## Existing architecture conflict

This is not merely a new convenience feature.

`docs/FOSSIL_INTEGRATION.md` already assigns these to **Study OS canonical evidence**:

- exact raw transcript/export bytes;
- normalized transcript;
- append-only learning event log;
- learning episodes and learner-state derivations.

It also requires transcript ingest to save immutable/raw transcript before normalized/derived processing.

The current learner-facing/runtime capability therefore appears incomplete relative to an existing Study OS ownership decision.

## P3 invariant

> No silent learner-evidence loss.

For transcript/source evidence, that means:

> Every learner-facing turn must be durably captured as append-only source evidence, or remain explicitly known as uncaptured/reconciliation-required. Semantic processing cannot be the only persistence path.

## Required logical ordering

```text
source turn
  -> append-only durable transcript/source record
  -> normalized turn
  -> learning events / attempts / operations
  -> derived learner + system state
```

A failure after source capture must not erase the source turn.

## Immediate design questions

- [ ] identify whether existing SQLite/private-evidence structures can represent immutable source turns without destructive schema repurposing;
- [ ] decide source-turn identity: conversation ID, message/turn ID where available, role, sequence/order evidence, content hash, original/source timestamp, local capture timestamp;
- [ ] decide whether source bytes live in the private immutable evidence store with indexed metadata in SQLite;
- [ ] decide whether live capture requires a new semantic MCP operation or can happen automatically before semantic dispatch;
- [ ] define exact retry/idempotency behavior for turn append;
- [ ] define outage-window backfill/reconciliation from reviewed transcript/export;
- [ ] preserve live-capture vs backfill provenance;
- [ ] fail closed on ambiguous reconciliation;
- [ ] extend `doctor` to expose missing/ambiguous transcript evidence where feasible;
- [ ] extend backup/restore coverage to transcript/source-turn state.

## Candidate operations — names not frozen

Potential semantics:

```text
append_conversation_turn
read_conversation_turns
reconcile_conversation
```

Do **not** freeze these names or enlarge the MCP surface until the PDD/SDD delta determines the smallest compatible design.

## Required tests

Extend the existing P3 durability TDD to prove at minimum:

- [ ] source turn commits before successful source-capture ACK;
- [ ] exact retry does not duplicate a turn;
- [ ] conflicting identity/payload reuse fails explicitly;
- [ ] source turn survives normalization/semantic processing failure;
- [ ] committed source turns survive process restart;
- [ ] backfill adds only genuinely missing turns;
- [ ] backfill rerun is idempotent;
- [ ] original/source time remains distinguishable from local recovery time;
- [ ] ambiguous reconciliation refuses automatic merge;
- [ ] backup/restore preserves turn identity, hashes, provenance and reconciliation state;
- [ ] public tests/logs never include real private learner transcript content.

## Boundary

Study OS remains the canonical owner of learner transcript/evidence.

FOSSIL remains optional downstream export/promotion and is not made a per-turn runtime dependency.

Raw private transcript stays local/private by default.

## First implementation action

Before coding, update the P3 durable-evidence PDD/SDD/TDD with the source-turn durability delta and inspect the current runtime schema/evidence store to choose the smallest architecture-compatible design.

Then Luna should implement test-first on disposable/synthetic conversations before a real GPT smoke test.
