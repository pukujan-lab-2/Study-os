# Issue #97: [WebApp] Decision layer: rules → hosted Jev → LLM cascade, Laya affect signals, day-one decision logging and switch criteria

- State: open
- Opened by Pukujan on 2026-09-24
- Original: https://github.com/Pukujan-lab/Study-os/issues/97
- Labels: enhancement

## Why this matters
Grading free text and picking misconceptions are the decisions that most affect learning evidence. They should run as a cheap, calibrated, logged, and swappable component, not as open-ended LLM chat. The deep-research report (`docs/webapp/DEEP_RESEARCH.md` §6–7) measured the options in the public `Pukujan/eval-lab`: hosted Jev scored 89.87% on blind rubric judging, while local zero-shot models (Laya, Kev-0.8B, Verdict) sat near the ~50% baseline.

## Outcome
An interpretation cascade behind one Jev-compatible `/v1/systemone` interface:
1. Rules first.
2. **Hosted Jev**, with a pinned version, for answer grading (`noul` per rubric point, `choice` pass/partial/fail) and misconception choice (`choice` + `none_of_these`).
3. **Laya-421M** via `laya-serve` on gravebuster, with `LAYA_API_KEY` set, only for frustration / wants-answer / sentiment, and only after per-type temperature calibration on Study OS labels.
4. The frontier LLM (#89) only on low confidence and for failed-step rewrites.

Next-step selection stays deterministic: rules + pyBKT + FSRS, with a bandit later and propensities logged from day one.

## Acceptance criteria
- [ ] Day-one `learn.decision` logging covers: state hash, question schema, model id/version, full distribution, confidence, τ, route, escalation, latency, cost, and later ground-truth labels with provenance (gold/silver).
- [ ] About 5% seeded audit sampling of auto-accepted decisions.
- [ ] τ is fitted per question type on a public split, and a blind split is held back. Startup fails on an unpinned or re-versioned model without a re-fitted τ.
- [ ] Contract tests pass for hosted Jev, Laya, and a stub through the same interface. Affect never changes grades, capability states, or the current step (model-based test).
- [ ] Switch criteria for the three upgrade paths are documented and a dashboard exists for them: (a) fine-tune ModernBERT/Laya, (b) fix the harness, (c) convert to a rule.

**Pukujan commented, 2026-09-24**

Route decision (owner-chosen): Jev handles tier-2 grading and misconception choice. It's called through the OpenRouter Decisions API with the model pinned to `typesafe/jev-1.13`, never `~typesafe/jev-latest` in production. Pricing is $0.042/M input with free output, and the context is 32K. The env var is `OPENROUTER_API_KEY`. The reference adapter is `typesafe-ai/system-one-adapter-python`.

Live probe results:
- 4 calls: a correct answer graded `pass` at p=1.0; an off-by-one answer graded `fail` at 0.93, with misconception `window_too_long` at 0.93; wants_answer came back `yes`; frustration came back 2.37 at confidence 0.55.
- 12-item mini grading set: 11/12 correct, and all 6 predictions at confidence ≥0.9 were correct. Each call took 0.16–0.26 s.
- Gotcha: `score` criteria must be an ordered array. Passing an object returns HTTP 400.

Details are in `docs/webapp/LLM_ROUTE.md` §5a (PR #96, checkpoint 100b806). Refs #83
