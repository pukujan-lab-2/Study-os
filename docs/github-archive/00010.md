## Purpose

Canonical P2 execution tracker for the learner model, curriculum, adaptive control, and promotion ladder. Study OS must improve what it records, models, teaches, and selects next without replacing canonical evidence/checkpoint state or letting an OSS donor/LLM silently own learner state.

Engineering verification is tracked separately in #21 and is a prerequisite for G5 advisory/canary or later.

## Architectural invariant

```text
canonical Study OS evidence/state
 -> versioned read-only LearnerSnapshot
 -> isolated component adapter
 -> structured DecisionProposal + rationale
 -> shadow/audit record
 -> reproduction/replay/live-shadow gates
 -> bounded live authority only after promotion
```

Non-negotiable: donor/adaptive libraries do not get direct SQLite/checkpoint ownership; candidate eligibility is deterministic and separate from ranking; hidden transfer/retention answers stay protected; every decision is reconstructable; disabling a component must not make canonical learner state unreadable.

## Promotion ladder

- G0 source/license/assumption audit
- G1 adapter conformance
- G2 donor reproduction
- G3 replay
- G4 live shadow
- G5 advisory/canary with accept/reject log + kill switch
- G6 bounded live authority
- G7 within-subject outcome comparison

### Verification prerequisite

**Do not advance a component to G5 or later until the relevant #21 verification gates are implemented and green.** In particular: static/type/version/architecture baseline, semantic property/state-machine tests, independent reference/differential checks, mutation/negative-control coverage, hidden engineering holdout boundary, and seeded learner-policy simulation.

## Next P2 work after #21 baseline

1. complete rich `LearnerSnapshot` projection;
2. build frozen replay corpus and G3 comparison reports;
3. run real G4 live-shadow learning sessions;
4. compare proposals against actual downstream behavioral outcomes;
5. add G5 advisory/canary acceptance/rejection logging + kill switch;
6. promote only bounded component authority with rollback/replay evidence;
7. expand curriculum only after the first slice demonstrates a trustworthy measurement/control loop.

## Completion condition

P2 is complete only when Study OS can reconstruct why a task/representation/assistance action was chosen, link it to canonical learner evidence, measure what happened afterward, survive independent verification, and replace/disable the component without losing learner continuity.
