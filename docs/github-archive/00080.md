# Issue #80: SOS-0002: Rebuild the sliding-window PIR lesson to follow the two goldens step by step

- State: closed (2026-09-24)
- Opened by Pukujan on 2026-09-24
- Original: https://github.com/Pukujan-lab/Study-os/issues/80

## Why this matters

The shipped sliding-window PIR lesson (`src/study_os/pir/registry.py`, canonical problem `sliding-window.max-sum-k.sep4.v1`) does not follow the two learner-calibrated goldens that Study OS already owns:

- `domains/dsa/sliding-window/golden/beginner-progressive-box-index-sum.v0.1.md`
- `domains/dsa/sliding-window/golden/beginner-sum-enumerate-append.v0.1.md`

Research found the shipped lesson has about 20 steps. It starts at `sum[i]`, so it skips position `p`, zero-based index `i = p - 1`, box size `k`, the box itself, and `i` moving the box. It jumps from `sum[i]` straight to the recurrence without the concrete successive sums (`sum[i+1]`, `sum[i+2]`, `sum[i+3]`) or the repetition of the recurrence from `S[0]` as `i` changes. In the code phase, the charts become only `problem_anchor` / `code` / `variable_roles`, so the array, index row, and box disappear. `first_window` and `boundary` are explain-only, and the lesson shows the full loop, which the goldens say not to do yet.

## Outcome

The shipped lesson follows the two goldens step by step, and deterministic tests fail when it drifts from them.

- Golden order: problem and `a` → position `p` → index `i = p - 1` → box size `k` → `i` moves the box → `sum[i]` → concrete successive sums → recurrence repeated from `S[0]` as `i` changes → `enumerate(a)` → `S[i] = ...` becomes `S.append(...)`.
- Golden rules: one picture, one new relation, and one tiny question per step. The same box chart persists into the code steps. Arrows and highlights appear only when introducing or correcting. Exercise charts leave out answer-revealing parts, such as the enumerate pair row. A correct answer is followed by "why" on the same chart. A wrong answer gets the correction on the chart, reassurance, a retry with a different example, and one more check before advancing. A partial answer keeps the correct part and isolates the missing step. Code changes storage only. Mastery is never claimed, and the end state stays `ASSEMBLED_MASTERY_UNPROVEN`.

## Scope

In scope:
- Rebuild the canonical asset in `src/study_os/pir/registry.py` and related assets. Scope is limited to what the two goldens cover (through `enumerate` and `append`).
- A conformance evaluator that mirrors `Pukujan/study-os-benchmarker` rules (`specs/VERIFICATION.md`, `evaluator` and `decomposition` at a pinned commit), plus an oracle for this lesson.
- Deterministic tests that fail on: a missing required bridge or step compared with the golden order, an ordering violation, a missing required representation (the box chart in code steps), a forbidden answer-revealing representation in exercises, too many new concepts in one step, and any mastery claim.
- Keep the existing controller, PARTIAL routing, and PIR mutation gate (`docs/P4_PIR_MUTATION_GATE.md`) passing. Update tests that encode the old step path.

Out of scope, recorded in the task file as follow-up rather than implemented: the parts 06-08 steps (loop assembly, `max`, the `else` bridge, the stop condition, `range(k)`). Also out of scope: runtime, schema, and MCP changes, and any private-repository content.

## Acceptance criteria

- [ ] The main path of the shipped asset introduces exactly the golden relations in golden order, one per step.
- [ ] Every probe has correct / incorrect routes that follow the golden feedback rules. Retry after an error uses a different example, and one more check comes before advancing.
- [ ] Box chart (array, index row, box, `k`) present in recurrence and append steps; exercise charts omit answer-revealing components.
- [ ] No learner-visible text claims mastery; the only exit is `ASSEMBLED_MASTERY_UNPROVEN`.
- [ ] New conformance tests kill each listed violation class with a targeted mutation.
- [ ] Full local CI equivalent green; required checks green on the PR.
