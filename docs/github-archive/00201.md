## Hosting convention: confirm the `/srv/study-os` layout and the tunnel network contract (proposal)

**Status: proposal. Nothing has been moved, and this issue authorizes no server change by
itself.**

> **This project is the prerequisite for the whole convention.** Study-os owns the single
> Cloudflare tunnel and the external `study-os_edge` Docker network that every other public
> project joins. The network name and the per-project alias scheme are the interface the
> other hosted projects depend on. Settle this one first.

### Why

The host `gravebuster` now runs ~50 Docker containers across ~15 projects, each deployed a
different way. Study-os is already at the target path and is the model in one respect — it
owns the tunnel — but it carries its own layout drift. The operator's words: *"lots of https
host flying everywhere."*

### The standard

**One project = one directory = one compose file.**

```
/srv/<project>/
  app/                      # the repository checkout
  docker-compose.yml        # top-level `name: <project>` pinned
  .env                      # chmod 600, gitignored
  .env.example              # committed
  PROJECT.json
  pg/  data/  ...
```

- **Exposure — loopback by default.** Every published port binds `127.0.0.1`. Never
  `0.0.0.0`, never the mesh IP.
- **Ingress — exactly two paths.** Public via the single Cloudflare tunnel over the external
  `study-os_edge` network; tailnet via `tailscale serve`.

### Where this project is now (observed 2026-10-07, read-only)

| Fact | Value |
| --- | --- |
| Deploy path | `/srv/study-os` — **already at the target path** ✅ |
| Repo checkout | `/srv/study-os/app` (the directory itself is not a git repo) |
| Compose file | `/srv/study-os/docker-compose.yml` |
| Services (5) | `api`, `backup`, `cloudflared`, `gateway`, `postgres` |
| Live bind | `127.0.0.1:18401` (gateway) ✅ loopback; also `127.0.0.1:18400` ⚠️ |
| Owns | Cloudflare tunnel `study-os-cloudflared-1`; external network `study-os_edge` |
| Public hostname | `study.design-bakery.com`, plus it serves every other project's hostname |
| Ingress shape | on-demand: `cloudflared` → `gateway` (wakegate, holds the `api` alias) → `api` |
| **Compose files** | **three under this directory** ⚠️ |

**Deviations**

- **Three compose files under one directory:** `/srv/study-os/docker-compose.yml`,
  `/srv/study-os/app/deploy/docker-compose.yml`, and
  `/srv/study-os/app.bak-20260927010625/deploy/docker-compose.yml` (the last inside a dated
  backup directory). Which one the running stack was created from is **not established**.
- **No `PROJECT.json`.**
- **No committed `.env.example`** (the `.env` itself exists, chmod 600).

### Target

The path is already correct. The work is consolidation and self-description:

| Service | Bind | Ingress |
| --- | --- | --- |
| `cloudflared` | none — egress-only tunnel connector | — |
| `gateway` | `127.0.0.1:18401` | the tunnel points here; holds the `api` alias on `study-os_edge` |
| *(unestablished)* | `127.0.0.1:18400` | identify the owning service |
| `api` | internal only | reached by `gateway` |
| `postgres` | internal only | not published |
| `backup` | none | scheduled |

**The exact changes** — the path is already correct, so this is consolidation and
self-description, no move:

1. Establish which of the three compose files the running stack was created from (see the
   open question), and reduce to one authoritative `/srv/study-os/docker-compose.yml`.
2. Pin `name: study-os` if not already pinned.
3. Add `PROJECT.json` and a committed `.env.example`.
4. Document the **network contract** the other projects depend on: the external network name
   (`study-os_edge`) and the per-project alias scheme.
5. Leave `app.bak-20260927010625` alone.

### Before any move

Re-run the probes this target was built on — `docker ps` with ports, `ss -tlnp`,
`tailscale serve status`, and `docker inspect` on the running container. This target was
written against a **2026-10-07** snapshot; if the host has drifted, the target is stale and
moving on it is the failure this whole exercise exists to prevent.

### Definition of done (read-only)

```bash
docker compose -p study-os config >/dev/null
docker ps --format '{{.Names}}\t{{.Ports}}' | grep study-os
ss -tlnp | grep -E ':1840[01]\b'                 # loopback only
docker network inspect study-os_edge --format '{{range .Containers}}{{.Name}} {{end}}'
curl -sI https://study.design-bakery.com | head -1
```

### Guardrails

1. **Do not change the tunnel or the `study-os_edge` network** without explicit operator
   direction — five other projects depend on them.
2. **Do not delete `app.bak-20260927010625`** as part of this; it is a dated backup and
   retires only on its own decision.
3. **Establish which compose file is authoritative before reducing to one.** The running
   container's labels say which file created it.
4. **No secrets** in this issue or in any committed file.
